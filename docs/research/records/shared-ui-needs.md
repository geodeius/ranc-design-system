# Existing UI Inventory — Shared Portfolio Needs

Status: In progress

This record describes stakeholder-reported product UI. It does not create or
approve design-system components.

## Record metadata

- Products in scope: Unify, Campaigns, Dipz, Glance, Rendezvous, and future
  products
- Evidence reference: Stakeholder responses provided during Stage 1 research
- Observation date: 2026-07-30
- Evidence type: Qualitative portfolio report; interfaces not reviewed

## Frequently occurring UI areas

The stakeholder identified:

- forms
- dashboards
- sidebars
- filters
- charts
- modals
- tables
- buttons
- navigation
- metric cards

These names describe observed product concepts. They are not approved component
registry entries, package exports, or API names.

## Reported current problems

- poor user experience
- inconsistent styling
- accessibility limitations

## Component-category priority

All component categories are considered important. No relative order within
actions, forms, navigation, feedback, data display, or overlays has been
selected.

An implementation sequence must therefore be derived from the Unify redesign
workflows, dependencies, accessibility risk, and engineering feasibility before
Stage 3 begins.

## Frequency

Qualitative only. The stakeholder accepted this level of frequency evidence for
Stage 1 and deferred occurrence counts, a product-by-product matrix, and journey
coverage.

## Candidate shared needs

The reported overlap suggests future investigation of:

- data-entry and validation patterns
- dashboard and metric presentation
- responsive primary and secondary navigation
- data filtering and tabular display
- data visualization foundations
- modal interaction and focus management

These are research directions, not approved components or patterns.

## Evidence limitations

- No interfaces, analytics, or source repositories were reviewed.
- The inventory does not establish anatomy, variants, behaviors, or ownership.
- Similar labels do not prove consistent requirements across products.
- “All categories” does not provide a build priority.
