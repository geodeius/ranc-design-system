# Stage 1 Plan — Research and Audit

Status: In progress

## Objective

Build an evidence-backed view of the existing Rancard product ecosystem before
defining shared foundations or selecting pilot components.

## Assumptions

- Product evidence and team access have not yet been provided in this
  repository.
- Repository templates may be created without deciding the outcome of the
  research.
- Product names, owners, priorities, and technology stacks must be supplied or
  directly evidenced.
- Existing registry entries describe the design-system platform, not the
  current product ecosystem.

## Risks

- Incomplete product coverage could bias foundation and component priorities.
- Screenshots can expose personal, customer, or production data.
- Similar appearance does not prove shared behavior or implementation.
- Interview claims can conflict with source-code or interface evidence.
- Selecting a pilot before engineering and accessibility constraints are known
  could invalidate later work.

## Workstreams

| Workstream                    | Initial state | Completion evidence                              |
| ----------------------------- | ------------- | ------------------------------------------------ |
| Product inventory             | Planned       | Reviewed record for each in-scope product        |
| Interface screenshot audit    | Planned       | Referenced, dated surface observations           |
| Existing component inventory  | Planned       | Evidence-backed repeated UI observations         |
| Color and typography audit    | Planned       | Current-state values with provenance             |
| Interaction pattern inventory | Planned       | Trigger, behavior, outcome, and platform records |
| Accessibility baseline        | Planned       | Automated and manual findings with limitations   |
| Engineering stack inventory   | Planned       | Evidenced platform and dependency constraints    |
| Product-team interviews       | Planned       | Attributed notes approved for repository use     |
| Inconsistency analysis        | Planned       | Cross-product comparison of observed patterns    |
| Pilot-product evaluation      | Planned       | Candidate matrix and explicit selection record   |

## Stage 1 deliverables

- [ ] UI inventory
- [ ] Pattern frequency report
- [ ] Current-state token inventory
- [ ] Accessibility findings
- [ ] Priority use cases
- [ ] Candidate pilot products
- [ ] Design-system opportunity map

## Exit criteria

- [ ] At least one pilot product is explicitly selected.
- [ ] High-frequency shared UI needs are evidenced.
- [ ] Product constraints are documented.
- [ ] Existing technical dependencies are understood.
- [ ] Research limitations and uncovered products are documented.
- [ ] No research placeholders are presented as approved specifications.

## Immediate inputs required

- list of in-scope products and environments
- safe access to representative interfaces or sanitized screenshots
- source repositories or dependency manifests where engineering audit is
  authorized
- product-team contacts and permission to record non-sensitive interview notes
- known accessibility reports or testing environments
- pilot-selection constraints and decision participants
