No production color tokens, palettes, semantic roles, themes, or modes have been approved.

## Purpose

Color will eventually communicate hierarchy, meaning, interaction, and brand relationships across supported platforms.

## Naming approach

No token names are approved. Future naming must follow the planned primitive, semantic, component, and theme hierarchy.

## Expected token hierarchy

The hierarchy is planned as primitive values, semantic roles, component roles, and theme or mode overrides. This is an architectural placeholder, not a token inventory.

## Platform considerations

Future definitions must document web, iOS, Android, and Figma mappings without assuming identical platform representations.

## Accessibility considerations

Future color decisions require contrast, forced-colors, non-color affordance, interaction-state, and theme validation.
